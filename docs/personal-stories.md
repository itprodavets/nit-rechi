# Personal stories inside topics

A topic is a context for recalling a real experience. Story practice defaults to a free first attempt, optional memory prompts and Anki vocabulary, then a preserved first version alongside a correction and explanation. Dialogue remains a separate optional form. No sentence-count target is imposed. A generous technical text bound protects browser storage and is not a learning target.

Implementation uses a separate pure `story-session` module and optional per-topic sessions so existing dialogue and daily sessions remain intact. `TopicStudio` connects topic selection, a reusable selection form and `StoryWorkspace`; map topic practice opens the same workspace. Drafts save to the original language/topic/session identity. Only explicit self-assessment updates progress; corrected versions cannot silently become independent first attempts. Written original, correction and notes remain in Materials after starting another story.

Starter examples become original fictional narratives with a setup, event, reaction and outcome, not accounts of the learner's own life. Known unchanged legacy starter fields may be upgraded, preserving user edits, links, positions and additional materials. No network AI is introduced: a copyable correction task contains the actual attempt and asks the learner's own chat to preserve facts, explain corrections and ask about ambiguous meaning. The correction can be pasted into a separate field.

Verification covers starting without words, independent drafts across topics/languages, frozen first attempts, reload, corrected-outcome handling, immutable migration of built-ins, retained materials, existing dialogue regressions, and mobile/desktop interaction. Delivery continues in the existing GitHub Pages repository.

Anki source collections stay distinct by original note GUID and retain all source deck IDs and hierarchy names. Deck choice is independent of language and mastery level, and available in the word library and topic preparation. Parent filters include child decks once per note. Reimport enriches older words with deck metadata without resetting their IDs, personal examples or practice results. Separate GUIDs are not merged by spelling or meaning. Text exports with an explicit deck column retain that source too. Earlier imports without saved deck metadata require reimport; names cannot be guessed from vocabulary.
